The gap

UPI can tell you the money is there.
It cannot tell you what it was for.

Razorpay has Agentic Payments on UPI Reserve Pay. The human pre-approves a spending limit. The rail records nothing about the purpose.

So when the customer says “my agent did that, I didn’t”, the merchant cannot prove otherwise.

Every agent purchase should carry a signed permission slip, and something should check the cart against it before the money moves.

Architecture

Rules first. One model call. Never the other way round.

One
The signed slip
AP2-inspired intent mandate: cap, categories, expiry, nonce, and the agent’s own playback of the request. Ed25519 over canonical JSON.
→
Two
12 deterministic checks
Signature, expiry, payee, method, line items, quantity, prices, category, discount, cap, agent identity, replay. Short-circuits on the first failure. Discount before cap, because the cap applies to the post-discount total.
→
Three
One model call
Only if every rule passed. Does this cart match what the human asked for? Strict typed JSON, a timeout, merchant text fenced as data, and the cap kept out of the prompt so it never re-decides arithmetic.
ALLOWBLOCKSTEP-UP · ask the human  Hash-chained either way. A degraded model call becomes STEP-UP, never ALLOW.
Why Razorpay

Agent Studio answers disputes.
This prevents and evidences them.

That dispute agent works on human transactions. Parchi is the other half: a pre-authorisation checkpoint sitting where the mandate meets the cart, on agent transactions, mapping field-for-field onto UPI Reserve Pay.

Strictly defense-only. Nothing in the repository can initiate a payment. Every path permits, refuses, or escalates.
